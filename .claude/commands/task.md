작업: $ARGUMENTS

CLAUDE.md의 레이어 / 코드 / 테스트 규칙을 그대로 따른다.

1. `gh issue create` 로 이슈 생성. 본문 형식:
   ## 목표         (한 문장)
   ## 완료 조건     (검증 가능한 문장들)
   ## 건드리지 않을 것

2. 계획을 제시하고 멈춘다 — 건드릴 파일, 추가할 함수, 작성할 테스트 이름 목록.
   이 사이클의 유일한 승인 지점이다.

3. (승인 후) 브랜치 생성. 이름은 `<type>/#<이슈번호>` 형식.
   type 은 Angular 규약: feat, fix, refactor, test, docs, chore
   예: `feat/#7`, `refactor/#12`
   이슈 번호는 1번에서 `gh issue create` 가 출력한 URL 끝의 숫자를 쓴다.

4. 테스트를 먼저 작성해 커밋, 푸시. 이 커밋에 구현 코드를 넣지 않는다.
   이 첫 커밋이 명세로 잠긴다. 이후 tests/ 는 수정할 수 없다(CI가 막음).

5. 구현. `npm test` 통과 확인 후 커밋, 푸시.

6. 테스트가 틀렸다고 판단되면 고치지 말고 멈춰서 말한다.

7. `gh pr create --body-file` 로 PR 생성. 본문 형식:
   Closes #<번호>
   ## 무엇을 바꿨나
   ## 테스트로 검증된 것   (테스트 이름을 그대로 나열)
   ## 미확인              (사람이 브라우저에서 확인할 절차. 없으면 "없음")

8. 머지하지 않는다.

작업 브랜치에서의 commit/push는 승인 없이 진행한다.
main 에는 직접 푸시하지 않는다.
